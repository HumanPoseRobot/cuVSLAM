# cuVSLAM 四目 VIO · 从原始版到 V1 的改动报告

比较范围为上游 `v17.0.1`（`51631ba358ea51262342f9ae649820d639363eb9`）到当前发布版 `runtime_reduced_v1`（`75466aa621ec892b0af651ceb04578e345cae603`）。原始提交是项目第一笔修复 `a640e92` 的直接父提交。两端 Git 差异覆盖 **66 个文件、7 笔提交**，其中包含实现、测试和回放示例。早期 CPU 修复 `249244d` 和 GPU 基础版 `e7cbb62` 都位于这段历史中。[完整源码差异](https://github.com/HumanPoseRobot/cuVSLAM/compare/51631ba358ea51262342f9ae649820d639363eb9...75466aa621ec892b0af651ceb04578e345cae603)

| 模块 | 原始版的行为或限制 | V1 累计改动与原因 |
|---|---|---|
| 世界系速度 | 部分四目惯性路径用相对位姿的平移量更新速度，平移坐标系可能与状态中的世界系速度不一致。 | 以两个世界位置的差除以实际帧间隔计算速度，覆盖纯旋转时位置不变的情况，减少速度误差进入下一帧惯性预测。 |
| IMU 预积分 | 收到 IMU 样本后增量维护多个积分区间，积分边界可能与实际相机时间不一致。 | 缓存有序样本，分别按相机帧、关键帧和最近有效位姿的时间锚点积分。对边界插值、按真实时长中点积分并传播噪声，保存分段时长供偏置更新后重积分。 |
| 参数传递 | 四目 Multisensor 的状态机和部分惯性 SBA 专家参数未接到实际调用点。 | 把状态机及 SBA 设置传入逐帧求解、关键帧触发和同步 SBA。补充固定关键帧数、迭代次数、稳健核尺度及 Python 字符串参数的支持，避免配置写入后未生效。 |
| 四路地图观测 | 单关键帧的每个地图点最多保存三路相机观测，侧向相机的可用地图点不足时缺少补充途径。 | 把容量增至四路，增加基于跨时刻跟踪的三角化能力，并检查基线、视差、深度和重投影误差。目的是保留可用共视约束，并在合适条件下补足侧向地图点。 |
| 重力初始化 | 惯性线性对齐失败时有平均加速度兜底。运动中的机体加速度会混入重力估计。 | 对齐失败时拒绝并重试，检查积分区间、旋转和状态的有限性。在米制初始化中保留视觉几何，把速度传播到各缓存帧时间，并清理不兼容先验。 |
| 前台视觉惯性求解 | 原四目前台由 IMU 预测提供位姿先验。 | 接入四目重投影与 IMU 预积分的两帧联合求解，维护位姿、速度、偏置及后验。V1 解析消去可条件求解的 6 维当前偏置，以 24 维系统求均值，完整双偏置后验仍用双精度 QR 边缘化。这样避免强偏置随机游走约束导致显式 30 维单精度求解病态。 |
| 后台滑窗 | 原版已有惯性 SBA。项目新增的 GPU 联合滑窗在原版中尚未接入。 | 接入多关键帧 GPU 滑窗与块 Schur 消元，先消除地图点再求导航状态。发布包启用四关键帧双精度 GPU Schur，并修正近 π 旋转对数及 CPU 参考求解的阻尼下降量，提高数值可靠性。 |
| 跟踪接受与重捕获 | 原版没有后续项目加入的四目联合候选接受检查及地图状态提交核验。 | 检查观测支持、重投影、速度和偏置修正；弱观测时限制惯性预测时长，从现有地图关联尝试重捕获。修复光流重跟踪复用缓冲区的残留，并在提交前核对地图快照、预先重积分受影响的边。提交失败时拒绝发布候选位姿。 |
| 四目回放入口 | 原版提供 SDK 与通用示例。 | 增加项目四目鱼眼回放入口和已验证的参数配置，输出轨迹、观测计数和输入指纹。发布包的固定前景多边形与投影有效区是输入配置，用于减少身体、手持物和无效像素对静态匹配的干扰。 |

## 原版与 V1 的同输入实测

从干净的上游 `51631ba` 重建原版，完整回放 HALO_851 `170302` 与五组 validation。V1 采用发布库已有的同输入轨迹。三版逐帧图像、时间戳和四路前景掩模哈希一致。原版和 V1 额外核对了有效相机标定，并由相同回放逻辑输入同一来源的 IMU。原版使用上游默认四目惯性求解配置，V1 使用发布配置。由此可以评估整版效果。

三维轨迹只按首个相机位姿对齐，尺度固定为 1。高度投影到同一段 V1 首次有效重力所定义的轴。速度由相邻有效位姿的三维位移除以实际时间间隔计算。2 m/s 是本次定位单帧跳变的诊断阈值。轨迹距离衡量两版差异，缺少外部真值时无法用来判断绝对精度。

两版六段均完整，合计均为 **0 帧无效位姿、0 次失跟、0 次地图重启、0 次重力中断**。因此本组实测没有观察到失跟率改善。原版有 5 次超过 2 m/s 的单帧速度，分别来自 170302 的 3 次和 195610 的 2 次。V1 为 0 次，GPU 中间版 `e7cbb62` 也已为 0 次。

## 已验证的改善及其归因

| 改动或现象 | 验证结果与边界 |
|---|---|
| 世界速度与 IMU 时间边界修正 | 早期提交添加了纯旋转速度、端点插值、缺失覆盖、噪声和偏置重积分回归用例。整版回放确认单帧速度尖峰减少，当前三版实验没有逐项拆分速度修正、时间边界、前台检查及重捕获各自的贡献。 |
| 前台候选检查、重捕获与地图提交保护 | `e7cbb62` 已在两段尖峰数据上达到零超限，V1 保持该结果。提交单元测试验证过失效快照和非有限状态的拒绝行为。六段都没有失跟，尚无这批数据上失跟改善的实测证据。 |
| 惯性初始化与缓存状态同步 | 初始化校验和速度时间传播有独立测试覆盖。六段都正常输出重力，现有结果无法量化初始化保护对失跟或高度的独立贡献。 |
| 偏置解析消元、双精度 Schur 与状态发布 | 偏置和滑窗测试验证了数值处理，强随机游走对照验证了显式单精度系统的敏感性。170302 相比中间 GPU 版的高度改善已在此前各三轮对照中复现。这次原版和 V1 的起终高度差仅 +1.7 与 +1.9 cm，高度峰峰值约 19 cm，说明 V1 在这段主要修复了中间 GPU 版的高度退化。整版对照无法把收益单独归给某一个求解改动。 |
| V1 相对原版的高度表现 | 高度没有一致改善。195610 的起终高度差绝对值由 6.5 增至 15.5 cm，203017 由 1.4 增至 15.9 cm。当前每段上游版仅测一轮，且缺少高度真值。 |
